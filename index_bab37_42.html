Bab 37 — Kenalan Git & GitHub

Selama ini kodemu tersimpan sendirian di laptop. Di dunia kerja, programmer menulis kode bareng-bareng — dan alat wajibnya adalah Git & GitHub. Bedanya di modul ini: guru kamu ikut turun tangan jadi rekan setim di proyek GitHub sungguhan.

37.1 Apa itu Git?

Git adalah version control system — alat yang mencatat setiap perubahan kodemu sebagai titik simpan yang disebut commit. Mirip save point di game: kalau ada yang rusak, kamu bisa kembali ke titik sebelumnya, dan kamu bisa melihat siapa mengubah apa, kapan, dan kenapa.

Tanpa Git, folder tugas biasanya berakhir seperti ini 😅

📁 tugas-kuis/
├── kuis.py
├── kuis_revisi.py
├── kuis_revisi2_FINAL.py
├── kuis_final_BENERAN.py
└── kuis_final_dari_guru (1).py

Dengan Git, cukup satu kuis.py — semua versinya tersimpan rapi di riwayat, dan dua orang bisa mengerjakannya bersamaan tanpa saling kirim file.

Git GitHub
Apa itu Program yang terpasang di laptopmu Website untuk menyimpan repo secara online
Butuh internet? Tidak — bisa offline Ya
Fungsi utama Mencatat riwayat (commit), branch, merge Berbagi repo, Pull Request, review, Issue
Analogi Kamera yang memotret tiap versi Album bersama tempat semua orang menaruh & mengomentari fotonya

Istilah yang akan sering kamu dengar:

Repository (repo)Folder proyek yang dilacak Git, lengkap dengan seluruh riwayatnya.
CommitSatu titik simpan: perubahan + pesan yang menjelaskan perubahannya.
BranchJalur kerja terpisah untuk mencoba fitur tanpa merusak versi utama.
RemoteSalinan repo di server, biasanya di GitHub. Nama panggilannya origin.
Push / PullMengirim commit ke GitHub / mengambil commit terbaru dari GitHub.
Pull RequestPermintaan di GitHub: “tolong review & gabungkan kodeku ke main.”
🤔  Tau nggak, kenapa namanya “Git”?  (klik buat lihat jawabannya)
😄  Git dibuat Linus Torvalds (pencipta Linux) tahun 2005 untuk mengurus kode Linux yang dikerjakan ribuan orang. “Git” adalah slang Inggris untuk orang yang menyebalkan — Linus bercanda bahwa ia menamai proyeknya seperti dirinya sendiri.

37.2 Instalasi & Konfigurasi

Kerjakan sekali saja di laptopmu. Centang tiap langkah sambil jalan.

Unduh GitWindows: buka git-scm.com → Download for Windows. Mac: buka Terminal, ketik git --version — macOS akan menawarkan instalasinya.
Saat instalasi (Windows), ubah dua opsi iniLayar Choosing the default editor used by Git → pilih Use Visual Studio Code as Git's default editor. Layar Adjusting the name of the initial branch → pilih Override the default branch name dan isi main. Opsi lain biarkan bawaan (termasuk Git Credential Manager).
Cek instalasiBuka terminal (di VS Code: menu Terminal → New Terminal), lalu ketik: 
git --version
Kenalkan dirimu ke GitNama & email ini tercatat di setiap commit. Pakai email yang sama dengan akun GitHub-mu supaya commit muncul di profilmu. 
git config --global user.name "Nama Siswa"
git config --global user.email "email-github@kamu.com"
Pengaturan anti-pusingTiga baris ini mencegah masalah yang paling sering bikin pemula bingung: nama branch, git pull yang menolak jalan, dan terjebak di editor Vim. 
git config --global init.defaultBranch main
git config --global pull.rebase false
git config --global core.editor "code --wait"
Buat akun GitHubDaftar di github.com/signup, lalu verifikasi emailnya. Pilih username yang rapi (misalnya nama aslimu) — repo-mu nanti bisa jadi portofolio.
💡 Cek semua pengaturanmu kapan saja dengan git config --global --list.

Bab 38 — Commit: Menyimpan Riwayat

Commit adalah “foto” proyekmu pada satu waktu. Sebelum memotret, kamu memilih dulu apa saja yang masuk ke foto — itulah gunanya staging area.

38.1 Tiga Area Git

📁
Working directoryFolder tempat kamu mengedit file
→git add
📦
Staging areaPerubahan yang dipilih untuk disimpan
→git commit
🗄️
RepositoryRiwayat commit (folder .git)
Catatan tutor: bayangkan mengirim paket. Meja kerja = working directory. Kardus = staging (kamu pilih barang mana yang masuk). Paket dikirim dan dicatat nomor resinya = commit, lengkap dengan label berisi pesan.

Kenapa harus lewat staging? Supaya satu commit berisi satu perubahan yang jelas. Misalnya kamu mengubah kuis.py dan soal.py untuk dua hal berbeda — kamu bisa menyimpannya sebagai dua commit terpisah.

38.2 Perintah Dasar

Perintah Fungsinya
git init Menjadikan folder sebagai repo Git (sekali saja per proyek)
git status Melihat file yang baru, berubah, atau siap di-commit — perintah yang paling sering dipakai!
git add kuis.py
git add .		 Memasukkan perubahan ke staging (titik = semua file)
git commit -m "pesan" Menyimpan isi staging sebagai commit
git log --oneline Melihat riwayat commit secara ringkas
git diff Melihat baris yang berubah tapi belum di-add

Pesan commit yang baik menjelaskan apa yang berubah, singkat (±50 karakter), dan ditulis seperti perintah: Tambah…, Ubah…, Perbaiki…, Hapus….

Bab 39 — Branch & Merge

Branch membuatmu bisa mencoba fitur baru tanpa takut merusak versi utama. Kalau berhasil, tinggal digabung (merge).

39.1 Konsep Branch

Commit X dan Y dibuat di branch fitur-skor tanpa mengganggu main. Commit M menyatukan keduanya.

  • main adalah versi utama yang harus selalu bisa dijalankan.
  • Fitur baru dikerjakan di branch sendiri, misalnya fitur-skor.
  • Saat pindah branch, isi file di folder ikut berubah — Git menukarnya otomatis.
  • Setelah selesai, branch di-merge ke main, lalu dihapus.
Catatan tutor: branch itu seperti fotokopi naskah untuk dicoret-coret. Naskah aslinya tetap aman. Kalau coretanmu bagus, baru disalin ke naskah asli.

39.2 Perintah Branch

Perintah Fungsinya
git branch Melihat daftar branch (tanda * = branch yang aktif)
git switch -c fitur-skor Membuat branch baru sekaligus pindah ke sana
git switch main Pindah ke branch lain
git merge fitur-skor Menggabungkan fitur-skor ke branch yang sedang aktif
git branch -d fitur-skor Menghapus branch yang sudah di-merge
Fast-forwardmain belum berubah sejak branch dibuat. Git cukup “memajukan” main ke ujung branch — tidak ada commit baru.
Merge commitmain dan branch sama-sama punya commit baru. Git membuat commit gabungan yang punya dua “orang tua” (seperti commit M di diagram).
💡 git checkout -b nama dan git checkout nama adalah versi lama dari git switch. Masih sering muncul di tutorial, fungsinya sama. Nama branch: huruf kecil, pakai tanda hubung, dan jelaskan isinya — fitur-skor, perbaiki-input.

Bab 40 — GitHub: Clone, Push & Pull

Sekarang repo terhubung ke internet. Kamu dan guru memegang salinan repo yang sama, dan GitHub jadi titik temunya.

40.1 Remote & Origin

💻 Laptop gurusalinan repo
⇄
push / pull
☁️ GitHubremote “origin”
⇄
push / pull
💻 Laptop siswasalinan repo
Perintah Fungsinya Kapan?
git clone URL Mengunduh repo dari GitHub, lengkap dengan riwayatnya Sekali di awal
git pull Mengambil commit terbaru dari GitHub & menggabungkannya Setiap mulai kerja
git push Mengirim commit-mu ke GitHub Setelah commit
git fetch Mengecek kabar terbaru tanpa menggabungkan Opsional
git remote -v Melihat alamat remote Kalau ragu
Penting: git status hanya tahu kondisi GitHub dari terakhir kali kamu pull atau fetch. Kalau guru baru saja push, laptopmu belum tahu sampai kamu menjalankan git pull.

40.2 Login ke GitHub dari Terminal

Password akun GitHub tidak bisa dipakai untuk git push. Pakai salah satu cara resmi ini — cukup sekali per laptop:

🪟 WindowsGit Credential Manager sudah ikut terpasang bersama Git. Saat push pertama, jendela browser terbuka → klik Sign in with your browser → izinkan. Login tersimpan.
🍎 Mac / 🐧 LinuxPasang GitHub CLI, lalu jalankan gh auth login → pilih GitHub.com → HTTPS → jawab Y untuk “Authenticate Git with your GitHub credentials” → login lewat browser.
💡 GitHub bisa meminta kamu mengaktifkan 2FA (verifikasi dua langkah) setelah mulai berkontribusi kode. Ikuti saja — pakai aplikasi authenticator di HP.

Bab 41 — Pull Request & Konflik

Begini cara tim profesional bekerja: tidak ada yang langsung mengubah main. Semua perubahan diusulkan lewat Pull Request, di-review, baru digabung.

41.1 Alur Kerja Tim (GitHub Flow)

  1. Buat branchgit switch -c tugas
  2. Commitadd & commit seperlunya
  3. Push branchgit push -u origin tugas
  4. Buka Pull Requestdi GitHub
  5. Review & diskusikomentar per baris
  6. Merge ke mainsetelah disetujui
  7. Pull & bersih-bersihpull main, hapus branch

Pull Request (PR) artinya: “Aku sudah selesai di branch ini, tolong cek lalu gabungkan ke main.” Di halaman PR, tim bisa melihat baris yang berubah, berkomentar per baris, dan memutuskan bersama. Kotak hijau di atas terjadi di website GitHub, sisanya di terminal laptopmu.

41.2 Code Review

Saat me-reviewJelaskan kenapa, bukan cuma apa. Beri saran yang konkret. Puji bagian yang bagus. Bahas kodenya, bukan orangnya.
Saat di-reviewReview bukan nilai rapor. Tanya kalau komentarnya belum jelas. Perbaiki di branch yang sama — PR otomatis ter-update. Balas, lalu klik Resolve conversation.

Saat mengirim review, GitHub memberi tiga pilihan:

  • Comment — komentar biasa, tanpa keputusan.
  • Approve — setuju, PR siap di-merge.
  • Request changes — ada yang harus diperbaiki dulu sebelum di-merge.

41.3 Merge Conflict

Konflik terjadi kalau dua orang mengubah baris yang sama di file yang sama, lalu Git diminta menggabungkannya. Git tidak mau menebak versi mana yang benar — kamu yang memutuskan. Isi file yang konflik akan terlihat seperti ini:

kuis.py — sedang konflik
def main():
<<<<<<< HEAD                              ← awal versi KAMU (Current)
    print("=== 🐍 KUIS SERU ===")
=======                                   ← pembatas
    print("=== KUIS PYTHON — KELAS PRIVAT ===")  ← versi GURU (Incoming)
>>>>>>> 3f9c2a1…                          ← akhir konflik + kode commit yang masuk
    skor = 0

Cara menyelesaikannya:

  1. Buka file yang konflik (git status memberi tahu namanya).
  2. Putuskan: pakai versimu, versi orang lain, keduanya — atau tulis ulang gabungan terbaik.
  3. Hapus semua tanda <<<<<<<, =======, >>>>>>>, lalu simpan.
  4. git add kuis.py → git commit → git push.
💡 VS Code menampilkan tombol di atas setiap konflik: Accept Current Change, Accept Incoming Change, Accept Both Changes, dan Compare Changes. Simulator di bawah punya tombol yang sama.
Catatan tutor: konflik itu normal, bukan tanda kamu salah. Programmer profesional menghadapinya tiap minggu. Kuncinya: tenang, baca, dan diskusikan dengan tim.

Bab 42 — Proyek Tim: Kuis Python

Saatnya bekerja seperti tim developer sungguhan: tugas dibagi lewat Issue, dikerjakan di branch masing-masing, lalu saling review — termasuk kamu me-review kode guru!

42.1 Issue: Kartu Tugas Tim

Issue adalah catatan tugas atau laporan bug di tab Issues repo. Setiap issue punya nomor (#1, #2, …), bisa diberikan ke orang tertentu lewat Assignees, dan diberi Labels seperti enhancement atau good first issue.

💡 Tulis Closes #3 di deskripsi Pull Request. Begitu PR itu di-merge ke main, issue #3 tertutup otomatis. Kata lain yang juga bisa: fixes dan resolves.

42.2 Daftar Tugas Proyek

Guru membuat issue-issue ini di GitHub (judul & isinya tinggal disalin). Tugas siswa memakai materi Bab 7–17 yang sudah kamu kuasai.

42.3 🤝 Misi 4 & 5 — Sprint Proyek

Dua sprint singkat. Di akhir, Kuis Python versi 1.0 dirilis — hasil kerja tim kalian berdua.

42.4 📡 Papan Pantau GitHub

Halaman ini bisa membaca aktivitas repo kelas langsung dari GitHub: commit terbaru, Pull Request, issue, dan siapa mengerjakan apa. Guru dan siswa melihat data yang sama dari perangkat masing-masing — jadi kalian bisa saling memantau tanpa harus satu layar.

  • Syarat: repo Public dan Data Kelas (Bab 37) sudah diisi.
  • Tanpa login, GitHub membatasi 60 permintaan per jam. Satu kali muat ulang memakai ±5 permintaan.
  • Papan ini hanya membaca — tidak pernah mengubah apa pun di GitHub.

42.5 Kebiasaan Developer Tim

Commit kecil, pesan jelasRiwayat yang rapi memudahkan mencari kapan bug muncul.

Langkah selanjutnya: sematkan (pin) repo ini di profil GitHub-mu sebagai portofolio, lanjutkan ide fitur bersama guru (timer, kategori soal, atau versi web dengan Flask dari Bab 25), lalu coba berkontribusi ke proyek open source lewat Fork.
